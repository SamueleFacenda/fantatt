## [Unreleased]
### Added
- Authorization model (G0.7): `fantatt-core` defines the five roles, the capability set, object scopes, and the default-deny policy of `docs/21-authorization-matrix.md`; route declarations, the authorize middleware, and the seeded role × route matrix test live in `fantatt-api`; decisions in `docs/adr/0011-authorization-model.md`.
- Route declarations in `fantatt-api`: every route registers through `authz::get`/`post`/`put`/`delete` with a required capability and object scope, so a route without a declared capability does not compile; a matched route missing from the declaration table is denied with 403 `capability-missing` (`ROUTE_UNDECLARED`).
- `[authz]` configuration section with the `superadmins` grant list (user ids in config or a comma-separated `FANTATT__AUTHZ__SUPERADMINS` variable), validated at startup; 403 denials carry `CAPABILITY_MISSING` with `details.capability` naming the missing capability and log a structured event.
- `crates/fantatt-api/tests/authorization_matrix.rs`: a seeded walk of anonymous callers and every role across representative object-scoped routes, asserting allow/deny per the matrix, plus a negative control proving an undeclared route denies every caller.
- API shell (G0.6): `GET /healthz`, `GET /auth/csrf`, `DELETE /auth/session`, `POST /api/v1/csp-report`, and `GET /openapi.json`; every other path answers 404 and a wrong method 405, both problem+json. Routes, middleware order, and configuration in `docs/20-api-shell.md`; decisions in `docs/adr/0010-api-shell-security-middleware.md`.
- Security middleware: per-response CSP with a fresh nonce (documented directives byte-exact) plus HSTS and nosniff, RFC 9457 problem+json envelope on every error, request-id middleware, CSRF double-submit as HMAC-SHA256 over the session id, governor rate limits parsed from configuration, a 1 MB body limit, and Idempotency-Key validation.
- `fantatt-api` session layer: a Postgres session store on the workspace sqlx 0.9 against the `tower_sessions.session` mirror table (ADR-0010), the `__Host-session` cookie with HttpOnly, Secure, SameSite=Lax, a thirty-day sliding window, and a twelve-hour absolute cap enforced by middleware.
- OpenAPI 3.1 document derived from the annotated handlers, served at `/openapi.json` and snapshot-tested against the committed `crates/fantatt-api/openapi.json`; regenerated by the `openapi_snapshot` example.
- `just api-serve` and `just api-demo` recipes: serve the shell against the dev database and curl the health check, a CSRF-rejected logout, a session with its token, and the OpenAPI document.
- Integration suite in `crates/fantatt-api/tests/`: health contract, default-deny fallbacks, an error battery that must all answer problem+json, security headers and cookie flags, the CSRF accept/reject matrix, rate-limit exhaustion to 429 with Retry-After, and the session round trip through the real store.
- `rand` 0.9, `hmac` 0.13, `sha2` 0.11, and `async-trait` 0.1 promoted from transitive to direct workspace dependencies (CSP nonces, request IDs, CSRF HMAC, and the hand-rolled session store on the workspace sqlx). The versions already resolve in `Cargo.lock` through `tower-sessions` and `sqlx-postgres`, so no crate enters the dependency graph; only `fantatt-api`'s own dependency list records the edges. Watchdog rows are recorded in `docs/dependency-watchdog.md`.
- Database schema and migration toolchain (G0.5): 28 tables in `migrations/` covering accounts, identity, competitions, leagues, squads, auctions, tournaments, ingest, notifications, and the append-only audit log, written as reversible numbered pairs (`<version>_<name>.{up,down}.sql`). Database-level enforcement of INV-1 (rating uniqueness), INV-4 (exclusive ownership), INV-6 (no duplicate player), INV-12 (budget), and the hash-chained append-only `audit_log` of docs/10-security.md §11. `tower_sessions.session` mirrors the DDL of `tower-sessions-sqlx-store` so one migration set owns the whole schema.
- `fantatt-test-support` (dev-only crate): every database-backed test boots a private `initdb` Postgres on a unix socket in a temp directory — no container, no CI service, no port. It also implements the revert half of migrate → rollback → migrate, which the sqlx `Migrator` does not expose.
- Dev shell gains `postgresql` and `sqlx-cli` (both from the pinned nixpkgs input, sqlx-cli matching the workspace sqlx 0.9.0). `justfile` gains `db-start`, `db-stop`, `db-migrate`, `db-reset`, `db-prepare`, and `db-offline-check`; the last one joins `just check` so the committed `.sqlx/` offline query data can never go stale.
- Schema conformance tests in `crates/fantatt-api/tests/db_schema.rs`: table snapshot, migrate/revert/migrate round trip, exclusive and shared ownership, budget rejection, audit append-only and chain, session-table shape, and identifier format.
- Local gate suite in the `justfile`: rustfmt check, clippy with complexity limits (functions ≤20 lines and ≤3 arguments via `clippy.toml`, `unsafe_code` denied workspace-wide), workspace tests, a comment-lead lint, and a gitleaks secret scan over staged changes. Bare `just` runs the whole suite.
- Git hooks managed by lefthook (from the pinned nixpkgs input): comment lint and secret scan on pre-commit, Conventional Commits validation on commit-msg, installed with `just install-hooks`.
- CI split into three jobs: PR gates (gate suite, full-history secret scan, commit-range validation), dependency audit, and artifact build on pushes to `main`.
- `CONTRIBUTING.md`: development setup, gate reference, commit format, and the branch and merge protocol.
- Nix workspace (flake-parts + crane + rust-overlay) pinning the Rust 1.99.1 toolchain.
- Nine-crate backend skeleton (`fantatt-core`, `-scoring`, `-reasoning`, `-ingest`, `-api`, `-jobs`, `-notify`, `-obs`, `-config`) with their end-state dependencies pinned. `rudof` defers to G1.9: its 0.1.12 release does not compile against the current releases of its `shacl_ast`/`srdf` family.
- Monorepo directory trees for `web/`, `nix/`, `deploy/`, `tests/{e2e,nixos,conformance}`, and `rules/`.
- Cargo-based `justfile` and a CI workflow gating on `nix flake check` plus a dependency audit.
- Domain core in `fantatt-core`: prefixed ULID identifiers, division tiers (`B2`…`D2`), ISO 4217 money, ratings with the provisional 2000-point default, and the roster calendar with the week-one zero-points rule (INV-8).
- Typed domain error taxonomy covering INV-1…INV-15: every violation carries a stable SCREAMING_SNAKE code the API layer mirrors into RFC 9457 problem+json types.
- Aggregates with their invariants enforced by constructors and mutations: `Squad` (fifteen-slot composition, tier matching, uniqueness, lock/unlock, same-tier bench substitution), `League` (lifecycle plus exclusive and shared ownership claims), `Membership` (budget spending), `Player`/`PlayerIdentity` (one rating per effective date, resolution states, audited merges), `Matchday` (completion only when every tie is decided), `PlayerAppearance` (singles/doubles shape, per-set scores), `Lot`/`Offer` (highest-and-open-window bidding), `DerivedScore` (rule version and derivation record required), `PurgeRequest` (thirty-day GDPR window with tombstoned managers), and `IdempotencyKey`.
- Property tests for roster generation, budget sequences, exclusive claims, matchday completion sets, bid ladders, idempotency keys, rating uniqueness, and the purge window.
- `proptest` 1.12.0 as a workspace dev-dependency (with the row in `docs/dependency-watchdog.md`), `serde_json` for wire-format tests, and the `serde` feature of the `time` workspace dependency.
- `cargo-llvm-cov` in the dev shell and a `just coverage` recipe for the line-coverage gate.
- `fantatt-config`: typed settings for every module of `docs/12-configuration.md` §2, with the defaults compiled in as TOML, an `env:VARIABLE` reference type for secret fields, kebab-case facade selectors (`embedded-rocksdb`, `http-api`, …), and every optional field present with an empty value so any layer can override it. The unused `validator` dependency was dropped from the crate.
- Layered configuration loader: compiled-in defaults → an optional TOML file → `FANTATT__` environment variables → `--set` CLI pairs, highest layer wins. Environment and CLI values are typed from the key they name, so a wrong type is reported as that key rather than as a parse failure. `FANTATT__CONFIG_FILE` and `FANTATT__ENV_FILE` steer the boot and are never read as settings; a variable naming a secret field is ignored.
- Startup validation: twenty-five typed rule violations, each naming the config key it belongs to (`session.cookie_name` must start with `__Host-` when `server.public_port` is 443, `privacy.deletion_grace_days` at least 30, zero ingest concurrency or interval, …), collected into a single abort. A literal secret in a config file, an absent required secret reference, an absent explicitly named config file, and a malformed env-file line abort the boot naming the offending key, file, or line. Resolved secrets print redacted and exposing one is opt-in.
- Eight boot tests in `fantatt-config` covering layered precedence (file beats defaults, environment beats file, CLI beats environment, unset keys keep the default) and every startup abort.

### Deprecated
### Removed
- `tower-sessions-sqlx-store` 0.15.1 from `fantatt-api`: it pins sqlx 0.8, and the workspace stays on a single sqlx 0.9 with the store implemented in-repo (ADR-0010). The `tower_sessions.session` migration mirror stays.
- `rudof` 0.1.12 from `fantatt-reasoning`: the release does not compile against the current releases of its `shacl_ast`/`shacl_validation`/`srdf` family (imported APIs were removed upstream), and pinning the whole family to its 2024 releases would be dependency drift. It returns with G1.9, pinned family plus a SHACL conformance test.
### Fixed
- Dev shell ships `llvm-profdata`/`llvm-cov` from `llvmPackages_23` (matching the LLVM release inside the pinned `rustc` 1.99.1) and exports `LLVM_COV`/`LLVM_PROFDATA`, so `just coverage` runs locally instead of failing with a raw-profile version mismatch.
### Security
- `lettre` bumped from 0.11.23 to 0.11.24, closing six SMTP advisories published 2026-11-17 (RUSTSEC-2026-0560 through RUSTSEC-2026-0565): command injection through missing dot-stuffing, panics on an all-whitespace `EHLO` reply and on a mailbox display name containing CR or LF, unbounded buffering of an SMTP reply, STARTTLS response injection, and messages for a quoted local part delivered to a different address. The same-minor bump needs no code change in `fantatt-notify`, and the watchdog row records the pin.
- `cargo audit` gate now runs from `.cargo/audit.toml`. Four transitive findings are upstream-blocked at the pinned direct dependencies and are recorded there with their blocking crate, accepted risk, and reopen trigger: `quick-xml` 0.37.5 via `oxigraph` 0.5.13, `rsa` 0.9.10 via `openidconnect` 4.1.0 and `rsa` 0.10.0-rc.19 via `crypto-glue` 0.2.2 (`webauthn-rs` 0.6.2), and `libsqlite3-sys` 0.30.1, which only enters `Cargo.lock` through sqlx's platform-gated sqlite driver and is absent from the x86_64-linux build graph. Excluding the deferred `rudof` family, the dependency tree carries no unresolved advisories.
- CSRF is enforced on the mutating route as HMAC-SHA256 over the session id with the configured secret (ADR-0010); `POST /api/v1/csp-report` is the one CSRF-exempt route because browsers report violations without a token.
