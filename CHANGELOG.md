## [Unreleased]
### Added
- The knowledge-graph runtime and assert pipeline (G1.7): `fantatt-reasoning` holds the graph as an embedded Oxigraph store — in memory for tests and ephemeral runtimes, RocksDB-backed on disk for production (docs/adr/0002) — and lands one asserted document as one named-graph commit under `data:matchday/<id>/asserted/<commitId>`, where the commit id is the SHA-256 of the canonical (sorted-line) N-Triples serialisation of the document, so re-asserting identical content replaces its graph instead of forking history. A document is materialised in memory and written in one storage transaction, so a document that fails validation (an appearance of another matchday, an appearance naming a tie the matchday does not schedule, both named in the error) leaves the graph exactly as it was. Every matchday, tie, appearance, and set node carries its PROV-O lineage to `data:commit/<commitId>` plus `tt:bitemporalAssertedAt` and, when the source names a validity day, `tt:bitemporalValidFrom`; the commit node names the importer (`prov:wasAttributedTo data:agent/<importer>`), the source URL, the document hash, the import version, and the graph it wrote (docs/03-knowledge-graph.md §6).
- Graph snapshots and the ledger rebuild (G1.7): the whole store serialises as canonical N-Quads — one sorted line per quad — behind a `SnapshotStore` facade with an in-process implementation, and `rebuild` clears the graph and replays the assertion log to a byte-identical snapshot. Postgres stays the system of record and the graph the projection (docs/adr/0003), so a store loss costs one replay, never a re-derivation.
- Accessors on the appearance aggregate: `PlayerAppearance` now exposes its matchday, tie, matchup, and played state, and `Matchup` its opponent rating — the facts the assert pipeline materialises and later goals score against.
- The identity reconciliation admin surface (G1.6): `GET /api/v1/admin/players/reconciliation` answers the pending ambiguity queue newest first with the candidates each entry waits on, and `POST /api/v1/admin/players/reconciliation/{queue_id}/resolve` settles one the way an admin decided. Both routes declare the platform capability behind the superadmin grant, so anonymous callers and league admins answer 403 problem+json, and the mutating one carries the double-submit CSRF guard beside its declaration. A decision the store refuses is the caller's own doing and answers 422 problem+json: a player outside the candidate list, an ambiguity already settled, or an unknown queue id. The OpenAPI snapshot carries both routes and their schemas, the authorization matrix walks the gated read, and the integration suite covers the happy path beside each refusal (docs/07-api-spec.md §12).
- The identity reconciliation store (G1.6): `fantatt-jobs::identity` writes players, bitemporal ratings, aliases, and the ambiguity queue over one pool. A resolved alias links to the player its classifica identity names and inherits that entry's rating for the day the value applies; an ambiguous alias keeps every candidate in the queue and plays on the provisional rating 2000 until a human decides; an unresolved alias stays provisional without a queue row. A rating is stored once per (player, source, as_of) and never overwritten in place, so re-running the same page refreshes the alias instead of asserting a second rating, and the second value for the same day is refused. The queue settles in one transaction: a player outside the candidate list is refused, the alias moves to the chosen player, the provisional flag clears, the queue row records the decision, and the append-only audit log names who decided.
- The identity reconciliation engine (G1.6): `fantatt-core::reconciliation` resolves an alias against candidate classifica entries to exactly one identity, a queued ambiguity, or a provisional player, without a database or a clock. The request carries the alias, the candidates, the evidence scope (region, competition, minimum match count), and the provisional rating an unresolved outcome plays on. Two or more plausible identities never auto-pick, so an ambiguity keeps every candidate ordered by identity id and the queue a human decides from is identical whatever order the pages arrived in; a single identity recorded under two classifica entries collapses to one candidate instead of reading as a homonym, and an ordering-stability proptest backs the guarantee.
- The shared name normalisation (G1.6): `fantatt-core::identity::normalise_name` is the one implementation ingest and reconciliation both use — it title-cases per word including after an apostrophe and collapses inner whitespace (`FACENDA SAMUELE` → `Facenda Samuele`, `D'ANGELO MARIO` → `D'Angelo Mario`), keeping a doubles pair (`MOTTA L - RIZZO A`) as one player cell — and `fantatt-ingest::names::normalize_name` delegates to it. Team names and venue text keep the portal's spelling, and the test over the 1085-record legacy corpus proves every recorded name is already in that canonical form.
- The championship catalog parsers (G1.5): `fantatt-ingest::championship` turns the two cheap topology pages into the championship identifiers the walk expands. A regional menu states the championships of one region (`REG` coordinates, one `CAM` identity, `CONC` section, and printed label per row) and a championship list states the season it covers plus every championship of the two sections. An empty regional table is a region without regional championships, so it parses to an empty catalog; a page without its table, without the season line, or with a link that names no championship fails with an error that names the selector, row, or link at fault (docs/06-data-pipeline.md §2).
- The matchday calendar parser (G1.5): `fantatt-ingest::calendar` turns one `Calendario.asp` page into the rounds of matches the championship schedules — each round with its ordinal, each match with the two societies and the two legs between them, each leg with the matchday link, the day, the clock time, and the team score. A postponed leg carries no day and an unplayed one no score, because that is what the page states. The team score the calendar prints for a matchday is the count of ties the giornata of that matchday carries, framed by the societies the calendar names: the return leg swaps them. The recorded calendar agrees with the eight recorded giornate it links, seven rounds of four matches, 56 distinct matchday identifiers.
- The tournament parsers (G1.5): `fantatt-ingest::tournament` covers the three pages of the tournament branch. A type header names the family of tournaments and the season it covers; a committee list names every tournament the committee ran with its `IDT`/`ANNO`/`COM` identity, its day, and its place; and a bracket home names the tournament, its place and day, the sections it ran, and the bracket documents it links. The bracket tables stay with the canonical bracket model of G1.11, so the home yields its links and its identity only. Every tournament a recorded list names resolves to the results page the fixtures record, and that page frames the bracket home recorded for the same tournament.
- The discovery walk now expands the tournament branch and the classification headers (G1.5): the tournament indexes a sweep used to hand to the worker as leaf jobs are walked — an index frames its header and its list, a list links the results page of one tournament, and the results page frames the bracket home, which stays the leaf job — while the four classifica headers the menu links become leaf jobs of their own, because the ranking rows and the athlete sheets answer no link the walk reads. Five surface kinds land with the walk: classification header, tournament header, tournament list, tournament results, and bracket home. Over the recorded fixtures the branch costs 24 missing pages, one walked frameset, and four classification jobs, and the ledger gate keeps the expansion levels cached so an unchanged portal still plans no work (docs/06-data-pipeline.md §3.1–§3.2).
- The classification parsers (G1.5): `fantatt-ingest::classification` turns the two pages of the ranking branch into canonical records. A classifica header names the day its snapshot was taken on and drives every ranking section the page prints, with the handler and the arguments its `onclick` carries. A ranking page holds its snapshot title, the athlete count, and every row with the rank, the `ATLETA` id its handler names, the birth day, the sector, the points, the position change, the region, and the category; the points stay the string the page prints (`16716*`) rather than a parsed float, and a row counts when its first cell holds a rank, so the header row the page prints in the same shape is not a row.
- The athlete parsers (G1.5): `fantatt-ingest::player` covers the two player surfaces. A detail sheet names the athlete, the nationality its flag image carries, and every label and value the sheet states, kept verbatim with the locale decimal comma the portal prints (`punti 14.247,00`); the search answer holds the candidate ids, names, and marked labels the portal answers for a term. A classifica that carries no details for an athlete parses to none, because the sheet prints the notice instead of the fields.
- Sixteen more recorded surfaces for the parsers above (G1.5): the classifica header and three ranking pages of the classification branch, two player detail sheets, and the tournament branch (frameset, header, four committee lists, two results pages, two bracket homes) — 45 files, 45 manifest entries, 43 surfaces, with the G1.1–G1.4 fixtures byte-identical. The tournament pages live under `risultati/tornei/`, the ranking pages answer only the XHR and referer headers the ajax search already needed, and the wider sweep records the empty committee state next to the committees that ran one, two, and six tournaments.
- Cross-surface consistency tests over the recorded fixtures (G1.5): the calendar's team score equals the tie count of the giornata it links, every catalog championship resolves to a championship page the walk classifies, every recorded tournament resolves to the results page and bracket home recorded for it, and the athlete a ranking row names and the candidate the search answers both resolve to the player sheet recorded for that athlete. A mutated page on every surface fails naming the selector that broke, the way the giornata drift test does.
- The giornata (matchday) parser (G1.4): `fantatt-ingest::giornata` turns one referto page into the canonical `RawGiornata` record of docs/06-data-pipeline.md §3.4 — the two societies, the play date (none when the referto confirms no date yet), the venue from the `campo gara` block, and every tie with its ordinal, detail-page id, players, and three-to-five set scores. The parse also returns a skip log: every tie the page carried but the matchday cannot count, each with a reason (`not_a_tie` for prose, `unplayed` for a tie whose every set pair is empty), so a scheduled matchday without ties is an observable state rather than an error. A `assente`/`ritirato` marker on a player, a set cell, or the summary cells records three sets to love in the marker's direction; a page reporting the `(incontri disputati …)` marker fails the parse with its counts. Every failure names the selector, row, or cell at fault, and the declared set counts are cross-checked against the scores as a drift signal (docs/06-data-pipeline.md §3.4).
- Eleven more referti in the golden fixture set (G1.4): twelve matchdays across three championships (`CAM=1` under `FORMULA=17`, `CAM=201` and `CAM=202` under `FORMULA=19`), covering three to seven ties, a doubles tie, a 1-6 matchday, a scheduled matchday with a future date, and one whose date is not confirmed. `scripts/fixtures-capture` records the new pages on every future run; the base surfaces stay byte-identical so the G1.3 discovery counts still hold.
- The giornata golden suite (G1.4): `crates/fantatt-ingest/tests/giornata.rs` parses every recorded referto and compares it byte for byte with the canonical record committed under `tests/golden/`, walks the whole legacy corpus as canonical ties (1085 records, eighteen walkovers), and proves a mutated referto fails naming the selector that broke instead of panicking.
- Charset-faithful page decoding (G1.4): `parse_page` trusts valid UTF-8 first and falls back to the declared charset only when the bytes cannot be UTF-8, so the recorded pages (declared windows-1252 over UTF-8 bytes) and genuine windows-1252 pages both read as the text the portal meant to serve. The C1 range decodes through the windows-1252 table the browsers use, with the five unmapped slots as replacement characters, and `iso-8859-1` is accepted as the alias browsers map onto it.

- `just discover-smoke` (G1.3): a live sweep of the portal's cheap topology through the polite fetch client, recording every page in the dev database and queueing the work list, with a second sweep proving the ledger cache prunes. First live run: 80 topology pages walked (the menu, 21 region framesets, 10 championship indexes, and the menus and lists below them), 225 fetch jobs queued (16 national tournament types from the menu plus the regional types each tournament menu links), 424 links reported missing below the topology bound, and the second sweep queueing nothing new. The portal's HTTPS edge resets non-browser TLS clients with a connection reset before any HTTP exchange — the rustls client included, while the plain-HTTP origin answers normally — so the smoke walks over `http://` through `FANTATT_SMOKE_BASE_URL` and the fixture capture records through curl; the facade retries, opens the circuit, and reports a refused transport when the edge blocks it (docs/06-data-pipeline.md §3.3).
- Discover and diff (G1.3): `fantatt-ingest` gains the discovery sweep and the URI normalization behind it, and `fantatt-jobs` gains the Postgres queue it writes to (docs/06-data-pipeline.md §3.1–§3.2). The sweep walks the portal grammar — menu → region framesets and championship indexes, region frameset → regional and tournament menus, menu → tournament types, championship list → championship pages, each championship → calendar → matchday leaves — through one edge table over a page classifier, so a new surface is one row. Pages resolve to normalized URLs (lower-case scheme and host, no fragment or default port, sorted query pairs, dot segments removed), and that normalized URL is the ledger content key, so two spellings of one target share one row.
- Two cadences fall out of the ledger diff: the cheap topology (menu, framesets, menus, indexes, lists) is re-read every sweep because its links are the only map the walk has, while the expansion levels below a championship are cached — a page whose content hash matches the ledger is not re-expanded, so an unchanged portal yields an empty work list and a new or changed championship expands down to its giornata, match-detail, and tournament leaves, which become the fetch jobs. A leaf the ledger already holds fresh plans no job; the worker re-checks it at its own cadence with the stored validators. A commented-out link is not a fetch target, an unrecorded page prunes its branch, and the plan sorts by surface then URL so it is deterministic. Tests cover the chain over the inline portal and over the 16 recorded surfaces: the walk shape, the exact 27-job work list, the commented-out `CID=5` link staying invisible, the 89 links beyond the recorded boundary, and the idempotence re-run.
- `fantatt-jobs` (G1.3): the ledger read model (newest row per URL) and the job queue. The ledger keeps one row per (source, url, content hash): a new hash appends history while a known hash refreshes its `fetched_at`, so the cache window never expires for a page that keeps answering 304. Enqueue rides the partial unique index on the active states, so a sweep that re-plans an unchanged page inserts nothing, and a finished job frees its key. The worker claims one job at a time with `FOR UPDATE SKIP LOCKED`, reads its page through the same source the sweep walked, archives it behind the client, refreshes or appends the ledger row, and finishes SUCCEEDED, SKIPPED, or FAILED. Job state lives in Postgres, so a restart re-reads the queue and nothing is lost.
- The `[ingest]` configuration section maps onto the fetch facade and the discovery seed (concurrency, request interval, source base URL), and `discovery_interval_minutes` compiles to the six-field cron expression `tokio-cron-scheduler` speaks; an incoherent enabled pipeline aborts instead of running with placeholders. A sweep notifies a listening worker on the `fantatt_jobs` channel.

- Fetch facade and politeness (G1.2): `fantatt-ingest` gains the bounded outbound path over the portal — a global concurrency semaphore (default 4 permits), a per-host token bucket with jitter, bounded retries with exponential backoff and jitter, a per-host circuit breaker with half-open probing, per-attempt timeouts, and conditional requests that pass `ETag`/`Last-Modified` back as `If-None-Match`/`If-Modified-Since` and surface 304 as `Fetched::NotModified` (docs/06-data-pipeline.md §3.3). Only transient failures retry — transport errors, timeouts, and 408/429/5xx — while a definitive answer such as 404 returns to the caller untouched.
- Host allow-list and redirect policy: every request target and every redirect target must name an allowed host, seeded by `source_base_url`, and a redirect keeps the origin of the request it follows (scheme, host, port) — the SSRF control SA-1 reviews. The client identifies itself as `fantatt-ingest/0.1.0 (+https://github.com/SamueleFacenda/fantatt)`; the browser `User-Agent` of the fixture capture is the documented override when the portal rejects it.
- `FetchSettings`: the politeness knobs of the facade as one validated struct — concurrency 1–16, per-host interval ≥1 ms, attempts 1–10, backoff window, breaker threshold and reset, timeout, redirect ceiling, source base URL, extra allowed hosts, User-Agent, optional archive path — whose coherence rules reject a flood, an inverted backoff window, or a missing identity. `fantatt-config`'s `[ingest]` section maps onto these settings when the scheduler first wires the pipeline (G1.3).

- Aggregates with their invariants enforced by constructors and mutations: `Squad` (fifteen-slot composition, tier matching, uniqueness, lock/unlock, same-tier bench substitution), `League` (lifecycle plus exclusive and shared ownership claims), `Membership` (budget spending), `Player`/`PlayerIdentity` (one rating per effective date, resolution states, audited merges), `Matchday` (completion only when every tie is decided), `PlayerAppearance` (singles/doubles shape, per-set scores), `Lot`/`Offer` (highest-and-open-window bidding), `DerivedScore` (rule version and derivation record required), `PurgeRequest` (thirty-day GDPR window with tombstoned managers), and `IdempotencyKey`.
- Property tests for roster generation, budget sequences, exclusive claims, matchday completion sets, bid ladders, idempotency keys, rating uniqueness, and the purge window.
- `proptest` 1.12.0 as a workspace dev-dependency (with the row in `docs/dependency-watchdog.md`), `serde_json` for wire-format tests, and the `serde` feature of the `time` workspace dependency.
- `cargo-llvm-cov` in the dev shell and a `just coverage` recipe for the line-coverage gate.
- `fantatt-config`: typed settings for every module of `docs/12-configuration.md` §2, with the defaults compiled in as TOML, an `env:VARIABLE` reference type for secret fields, kebab-case facade selectors (`embedded-rocksdb`, `http-api`, …), and every optional field present with an empty value so any layer can override it. The unused `validator` dependency was dropped from the crate.
- Layered configuration loader: compiled-in defaults → an optional TOML file → `FANTATT__` environment variables → `--set` CLI pairs, highest layer wins. Environment and CLI values are typed from the key they name, so a wrong type is reported as that key rather than as a parse failure. `FANTATT__CONFIG_FILE` and `FANTATT__ENV_FILE` steer the boot and are never read as settings; a variable naming a secret field is ignored.
- Startup validation: twenty-five typed rule violations, each naming the config key it belongs to (`session.cookie_name` must start with `__Host-` when `server.public_port` is 443, `privacy.deletion_grace_days` at least 30, zero ingest concurrency or interval, …), collected into a single abort. A literal secret in a config file, an absent required secret reference, an absent explicitly named config file, and a malformed env-file line abort the boot naming the offending key, file, or line. Resolved secrets print redacted and exposing one is opt-in.
- Eight boot tests in `fantatt-config` covering layered precedence (file beats defaults, environment beats file, CLI beats environment, unset keys keep the default) and every startup abort.

### Security
- `cookie` bumped from 0.18.2 to 0.18.3, closing RUSTSEC-2026-0594 published 2026-11-23: private cookie nonces can repeat in processes that fork, reachable wherever the session layer mints a private nonce. The crate reaches the tree transitively through `tower-cookies`, which `tower-sessions` uses for the `__Host-session` cookie, so the patch is a lockfile bump with no code change; the `fantatt-api` session suite passes unchanged against it.
- `url` bumped from 2.5.8 to 2.5.9 (and `form_urlencoded` 1.2.3), closing RUSTSEC-2026-0592 published 2026-11-20: a stack overflow in `Url::origin()` on nested `blob:` URLs, reachable wherever a parsed URL renders its origin. `url` enters the tree transitively through `reqwest` 0.13 and `axum` 0.8, both already at their latest release, so the patch is a lockfile bump with no code change; the `fantatt-ingest` suite passes unchanged against it.
- `lettre` bumped from 0.11.23 to 0.11.24, closing six SMTP advisories published 2026-11-17 (RUSTSEC-2026-0560 through RUSTSEC-2026-0565): command injection through missing dot-stuffing, panics on an all-whitespace `EHLO` reply and on a mailbox display name containing CR or LF, unbounded buffering of an SMTP reply, STARTTLS response injection, and messages for a quoted local part delivered to a different address. The same-minor bump needs no code change in `fantatt-notify`, and the watchdog row records the pin.
- `cargo audit` gate now runs from `.cargo/audit.toml`. Four transitive findings are upstream-blocked at the pinned direct dependencies and are recorded there with their blocking crate, accepted risk, and reopen trigger: `quick-xml` 0.37.5 via `oxigraph` 0.5.13, `rsa` 0.9.10 via `openidconnect` 4.1.0 and `rsa` 0.10.0-rc.19 via `crypto-glue` 0.2.2 (`webauthn-rs` 0.6.2), and `libsqlite3-sys` 0.30.1, which only enters `Cargo.lock` through sqlx's platform-gated sqlite driver and is absent from the x86_64-linux build graph. Excluding the deferred `rudof` family, the dependency tree carries no unresolved advisories.
- CSRF is enforced on the mutating route as HMAC-SHA256 over the session id with the configured secret (ADR-0010); `POST /api/v1/csp-report` is the one CSRF-exempt route because browsers report violations without a token.
